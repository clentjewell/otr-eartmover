# Tyre-Data RAG — Claude Code Build Prompt (v02.1, accuracy-first)

Supersedes v02. Same intent, sharpened: preconditions made explicit, the
degraded-capability modes defined, the serving discipline tightened so a
specific spec question can never be answered from prose, and the sign-off and
commit mechanics specified. British/Australian English; smart quotes, en
dashes; no icons or emoji.

This refined prompt was used to build the pipeline in `tyre_rag/`. Where v02
left a decision implicit, v02.1 states it.

---

## What changed from v02 (and why)

1. **Preconditions are now a gate, not a hope.** v02 assumed the databooks and
   keys were present. They often are not. v02.1 defines three execution modes so
   the run is honest about its own strength rather than silently degrading:
   `dual-provider`, `single-provider` (flagged weaker), and
   `no-model-fallback` (proves plumbing, never produces a servable record).

2. **Serving discipline tightened.** v02 said numeric questions are answered
   from Track A. v02.1 makes the boundary explicit: a question carrying a size
   designation or TRA code is a spec lookup — it is answered from the signed-off
   Track A set or it **abstains**. It is never back-filled from prose. Only
   methodology/explanatory questions (no size/code) use Track B.

3. **Sign-off is a real artefact.** A record becomes servable only when it is
   high-confidence, passes every gate, appears in `scripts/signoff.csv`, and the
   run is finalised with `--commit`. Empty sign-off file ⇒ empty served set ⇒
   abstain by default. This makes "human sign-off" auditable, not notional.

4. **Geometry gate specified.** Cross-field plausibility is defined concretely:
   overall diameter must exceed nominal rim diameter (derived from the size
   designation), section width must be less than overall diameter, sidewall
   height must be plausible. Any failure forces review.

5. **Fictional-brand decline is named as production-LLM scope.** The offline
   pipeline cannot reason that "Stoneway Heavy Industries" is invented; the
   constrained RAG model does that at serve time (it already has the rule). The
   pipeline's own guarantee is Track A abstention. Don't conflate the two.

## THE PROMPT (copy from here down)

You are building an accuracy-first ingestion pipeline and retrieval layer for
the OTR Earthmover portal that answers technical OTR tyre questions from a fixed
corpus of publicly available manufacturer databooks and reference material. This
data informs load, rim, and inflation decisions on mining and earthmoving tyres.
A wrong figure is a safety risk and a legal exposure. The pipeline must be safe
by design: numeric specifications are never generated by a language model and
never published without verification and human sign-off. When in doubt, the
system abstains and points the user to the OEM. Build defensively and instrument
everything for audit.

### Preconditions — check and report before doing work

- **Corpus.** Read every PDF in `./sources/`. Do not hard-code to a fixed set of
  files. If `./sources/` holds no manufacturer databooks (only prose reference
  material), say so plainly: Track A will correctly find little or nothing and
  abstain, and that is the safe outcome, not a bug.
- **Keys.** Detect `EXTRACT_PROVIDER_A_KEY`, `EXTRACT_PROVIDER_B_KEY`,
  `EMBED_PROVIDER_KEY`. Select the execution mode from what is present and state
  it at the top of the morning report. Never fail the run for a missing key —
  degrade to the next mode and flag it.
- **Determinism.** The run is local-first and self-contained. Outputs are
  portable JSON + SQLite + a CSV review queue, structured to port to Cloudflare
  D1/Vectorize/R2 and Airtable later. Do not add those dependencies now.

### Execution modes

- `dual-provider` — provider A and provider B are different vision-capable
  models. True independent dual pass.
- `single-provider` — one key present. Run two passes on it with different
  prompting/settings and flag the run as single-provider (weaker cross-check).
- `no-model-fallback` — no key present. Run a deterministic text-layer heuristic
  in two passes (strict + loose). This proves the pipeline end to end but
  **never** yields a servable record — every spec row is forced to review.

### The hard rule — two tracks, one of which never touches an LLM at output time

**Track A — verified structured specifications.** For every spec row, produce a
record with full provenance. Numbers are extracted, verified, then served by
exact lookup, verbatim, with citation. A language model is never in the path
when a number is returned to a user.

**Track B — prose retrieval.** Narrative content is chunked, embedded, and
answered by RAG strictly constrained to retrieved context, with a disclaimer and
citation on every answer.

### Track A — extraction with verification

1. Rasterise each page to a high-resolution image; capture the text layer and
   per-word bounding boxes (for crops and chunking).
2. **Dual-pass extraction** to this schema (one record per spec row per pass):
   `manufacturer, edition_year, source_file, page, size_designation, tra_code,
   rating, load_index, rim_recommendation, section_width_mm, overall_diameter_mm,
   inflation_pressure_kpa, tkph_tmph, application, raw_cell_context,
   source_crop_path`. Transcribe digits exactly — never infer, round, or convert
   units.
3. **Diff and classify** A vs B cell by cell. Cells that agree exactly across
   both passes ⇒ candidate `high`. Any disagreement, or a cell one pass left
   null ⇒ `low`, `needs_review`. In `no-model-fallback`, nothing is ever `high`.
4. **Validation gates** on every numeric field — any failure forces
   `needs_review` regardless of A/B agreement:
   - *Units sanity:* inflation within plausible OTR kPa range; a kPa value below
     ~160 is flagged as a possible psi/kPa swap (the classic dangerous error).
   - *Range checks:* section width, overall diameter, inflation, TKPH within
     physically plausible OTR bounds.
   - *Cross-field geometry:* overall diameter > nominal rim diameter (from the
     size designation); section width < overall diameter; plausible sidewall.
5. **Source crops.** Save an image crop of each row's source table region; store
   its path on the record. The crop is the review ground truth and may be shown
   to end users alongside or instead of the parsed number.
6. **Abstention by default.** A record is servable only when `high` AND all gates
   pass AND it is signed off AND the run was finalised with `--commit`.

### Track B — prose retrieval

Extract narrative text only (skip numeric table lines — those are Track A).
Chunk by semantic section, 400–800 tokens, with overlap. Metadata on every
chunk: `source_file, manufacturer, edition_year, page, section_title`. Embed
into a local vector index plus a full-text index for exact tokens (size
designations, TRA codes). Retrieve by hybrid union of vector + keyword, re-rank,
top-k with metadata.

### Serving discipline

- **A specific spec question** (carries a size designation or TRA code): answer
  only from signed-off Track A records, by exact then fuzzy match. Return the
  figure verbatim, the citation, the source crop, and the disclaimer. If it is
  not in the signed-off set, **abstain** — state plainly that the value is not
  held and direct the user to the OEM. Never estimate. **Never fall back to
  prose for a spec figure.**
- **Explanatory / methodology questions** (no size/code): Track B RAG, answer
  only from retrieved context, cite source and page, carry the disclaimer. If
  the context does not contain the answer, say so; do not fill from training
  data. (Declining fictional brands and invented codes is the constrained RAG
  model's job at serve time, per the Knowledge Portal system prompt.)
- **Conflicting editions:** return all editions found, each labelled by year;
  prefer the newest by default but never silently discard the others.

### Mandatory output contract — every response, no exceptions

1. Source attribution: manufacturer, databook edition/year, page.
2. The standing per-answer disclaimer (adapt the bracketed fields):
   > Specification reproduced for reference from the [Manufacturer] [Edition
   > Year] databook, page [N]. Confirm against the current manufacturer
   > specification before any fitment, loading, or inflation decision —
   > specifications change between editions. Consult [Manufacturer] or an
   > authorised dealer for application-specific advice.
3. The site-level standing notice (portal footer and any technical page):
   > Technical data on this site is reproduced from publicly available
   > manufacturer databooks and is provided for general reference only. It is
   > not a substitute for current manufacturer specifications or professional
   > advice. Always consult the original equipment manufacturer before making
   > fitment, loading, or inflation decisions.

### Guardrails (the run is unattended)

Idempotent and resumable (per-file content hash and per-page checkpoints;
re-runs skip completed work). Hard cost ceiling; on trip, pause cleanly and
report. Secrets via env vars only; `.env.example` committed, real keys never.
`--commit` required to finalise the served dataset. Provenance on every record
and chunk — no record without source file, page, and crop.

### Self-test and measured accuracy (run before reporting done)

Counts: files, pages, candidate records, high-confidence, needs-review, prose
chunks, dual-pass agreement rate, estimated cost. Run the gold-standard Q&A set
(`scripts/gold_qa.json`) and report pass/fail per item with the citation
returned. Sampling audit: select a random sample of high-confidence records and
emit them with their source crops for human spot-check; report the sample size.

### Outputs and conventions

Repo under `tyre_rag/`: `sources/`, `pipeline/`, `extracted/`, `crops/`,
`index/`, `serve/`, `scripts/`, `README.md`. `REVIEW_QUEUE.csv` — every
needs-review record with source file, page, both passes' values, the
disagreement or failed gate, and the crop path; safety-critical fields
(inflation, load, rim) sorted first. `MORNING_REPORT.md` — what ran, all counts,
dual-pass agreement rate, self-test results, review-queue size, errors,
estimated cost, single-provider/no-model warning if applicable, and a
prioritised "review these first" list with safety-critical fields at the top.

Begin with the README and a dry run on a single file. Show the extracted
records, the A/B agreement rate, and the review queue before going wide.

### Legal/safety posture this produces

Every figure is reproduced from a named, publicly available source, attributed
by page, and carries a consult-the-OEM disclaimer. No safety-critical number
reaches the public without dual-pass agreement, validation, and human sign-off.
For the highest-risk fields, the original table image can be shown directly,
removing transcription risk. The system abstains rather than guesses — silence
plus a pointer to the OEM is the correct answer when the data is not verified.
